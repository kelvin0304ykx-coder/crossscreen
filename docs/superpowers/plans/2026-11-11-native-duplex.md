# 双向自然跨屏实现与验收

目标：Mac 在左，触控板向右到 Windows；Windows 鼠标向左到 Mac。每套键盘跟随同机指针。保留已有身份、文件剪贴板和回退入口。

用户已选择自然双向并要求继续开发。实现选择：Python + Win32 / Quartz 原生接口，由跨屏实现输入路由、控制权与连接，不替换为另一款键鼠共享引擎。复用项目已有证书双向认证。

## 设计

- TCP 连接角色继续沿用现有配置，仅决定谁监听，不再决定输入方向。双方完成版本和布局握手后才允许捕获。
- 监听方序列化控制权申请，每次发放递增 epoch。任何旧 epoch 的输入和归还均丢弃。领取完成之前短暂缓存输入，有上限和超时，失败回本机。
- 每次最多一套键鼠控制对端。接收端发生实体输入时立即恢复本机，通知撤销旧控制权；争抢由监听方按收到的申请排序。同机键盘跟随当前指针。
- 原生注入事件打标记并排除捕获；不保存键盘文本或事件日志。断线、停止、超时、系统撤销捕获时释放注入的按键/按钮和源端抑制状态。
- Ctrl+Alt+Shift+F12 紧急恢复本机。跨回边缘归还，而不是重启连接。过边缘后设内缩距离避免立刻弹回。
- 控制/输入独立于大文件通道；帧有长度限制，发送队列有上限，拥塞时断开并释放，不延迟重放旧输入。
- 原模式保留为可选择回退；开发候选不得冒充已真机验收的正式版本。

## 任务

1. `duplex.py` 与 `tests/test_duplex.py`：先测双向领取、返回、竞争、迟到输入、断开释放、握手不同版本与有限队列。
2. `input_keys.py`、`input_windows.py`、`input_macos.py`：实现两端原生捕获/注入，统一物理键码；验证结构体和映射，原生窗口接收事件与注入回环检查。
3. `native_engine.py`：连接 Qt、核心状态与原生后端，保证 startup/stop 对称与失败释放。实现基础文字/图片剪贴板替代原引擎能力，保留现有文件通道。
4. 界面引擎选择、配置兼容、打包包含新模块，旧配置与配对保持可用。对齐拖放输入来源。
5. 执行完整测试、候选打包、独立审查。核验 Mac 安全入口后构建同源码并真机验收，缺失权限须据实报告，不能以 mock 代替。

## 必验场景

双向连续过屏/回屏；换用另一套实体键鼠；按住修饰键跨屏与释放；长按/重复；两边同时申请；旧输入迟到；网络中断；停止重启；睡眠恢复；剪贴板媒体与文字回归；文件拖动；中文输入与触控板滚动。Mac 辅助功能只由用户确认，不能修改 TCC。
